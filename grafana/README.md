# Grafana Dashboards

Importable Grafana dashboard for surveiller, generated from the actual
Prometheus metric set exported by `internal/metrics` (see
`grafana/dashboards/surveiller.json`).

## Dashboard

- **`grafana/dashboards/surveiller.json`** — "Surveiller / Ping Monitor"
  - Stat row: total / OK / WARN / DOWN / UNKNOWN targets + overall up ratio
  - RTT trend (all targets: max / avg) — time series; aggregated lines so a
    single slow target can't squash the y-axis
  - RTT by target (avg over selected range, ms) — horizontal bar chart,
    per-target values stay readable regardless of scale differences
  - Avg RTT by group (current)
  - Availability by target (up fraction, last 5m) — lowest first
  - Target status over time / Status composition (stacked)
  - Template variables: Prometheus datasource, `instance`, `target`, `group`

## Metric names used (keep in sync with `internal/metrics/metrics.go`)

| Metric | Labels | Type |
|---|---|---|
| `surveiller_targets_total` | — | gauge |
| `surveiller_targets_ok` | — | gauge |
| `surveiller_targets_warn` | — | gauge |
| `surveiller_targets_down` | — | gauge |
| `surveiller_targets_unknown` | — | gauge |
| `surveiller_target_up` | `target`, `address`, `group` (+ `instance` via Prometheus) | gauge |
| `surveiller_target_rtt_ms` | `target`, `address`, `group` | gauge |

> The exporter does not emit `HELP`/`TYPE` comments, so add them to the
> Prometheus data source scrape config if your Prometheus complains about
> unknown types, or file a separate issue to add them in the exporter.

## Regenerating

The dashboard JSON is generated by `tools/gen_grafana_dashboard.py` so panel
queries stay in sync with the exporter code:

```bash
python3 tools/gen_grafana_dashboard.py
```

If you edit the exporter (`internal/metrics/metrics.go`) and change metric
names or labels, update the generator and re-run it.

## Importing

1. Configure `metrics.listen` (e.g. `9100`) and `metrics.mode=both` in
   `surveiller.conf` (or `--metrics-listen` / `--metrics-mode`).
2. Let Prometheus scrape `http://<host>:9100/metrics`.
3. Grafana → Dashboards → New → Import → paste the file contents (or upload
   `grafana/dashboards/surveiller.json`), pick your Prometheus datasource.
4. `metrics.mode=per-target` alone leaves the stat row empty; `aggregated`
   alone leaves the per-target panels empty. Use `both`.

## Provisioning (optional)

Drop the JSON into a Grafana filesystem provisioning path, e.g.
`/etc/grafana/provisioning/dashboards/`:

```json
{
  "apiVersion": 1,
  "providers": [
    {
      "name": "surveiller",
      "folder": "Surveiller",
      "type": "file",
      "options": { "path": "/etc/grafana/dashboards" }
    }
  ]
}
```
